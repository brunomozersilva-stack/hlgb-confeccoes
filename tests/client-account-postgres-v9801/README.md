PostgreSQL synthetic fixture; no HLGB commercial tables, credentials, RPC, browser or permissions. Proof of atomic unit of work, global reference, selected note/title revision checks, oldest-first server allocation, residual independent balance and one Hub entry. A fault at final Hub insert must roll everything back. Lab roles are intentionally direct-table grants: NOT a production access design. Production canonical invoices, event/credit evidence, authorization, existing Hub forecast/actual reconciliation, WAL, immutable receipt readback, opening and reversal persistences, simultaneous sessions and migration remain pending. The synthetic accounts are preseeded with independent balances; no date is invented. Never deploy this SQL to Supabase.

Concurrent test: two simultaneous sessions for one reference return the identical receipt; a competing reference with stale revision must fail, with exactly one Hub movement and one note/title update. This validates the synthetic function only, not actual commercial WAL, permissions or concurrent legacy writers.

Forecast reconciliation extension: one synthetic forecast row per title; verified balance must equal note/title open amount, locked alongside them. Partial receipts reduce planned inflow, full receipts close it without deleting the forecast; actual Hub receipt remains one per reference. Failed Hub insert rolls forecast back. Divergent forecast is blocked and concurrency checks one reduction. Real Hub data representation, permissions and synchronization are NOT proven. No deployment or migration.

## Prévia combinada de recebimento com saldo residual
Contrato JS une a proposta de saldo independente e o payload de nota/título sem criar duas entradas no Hub. Exemplo sintético: saldo anterior R$20, recebimento R$100, R$70 quitam a nota, R$30 reduzem o saldo independente e deixam R$10 de crédito. A saída é somente prévia: uma entrada esperada de R$100, duas atualizações documentais propostas e um evento de saldo independente. Revisões e referência verificadas; repetição exige confirmação independente. Sem RPC, gravação, saldo oficial ou afirmação de atomicidade; o fluxo integrado real continua pendente. CI passa a executar os dois contratos JS quando os arquivos relacionados mudam.
